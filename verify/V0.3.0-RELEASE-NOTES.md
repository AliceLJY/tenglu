# v0.3.0 — 文本锚点成为默认处理路径

## 本版变化

- Android 默认使用文本锚点路径：对选定帧逐帧做 ML Kit OCR、文本锚点位移、失败自检和几何去重；微信中纯坐标无法判断的气泡只局部解码文本框区域判定发言人。
- 现有拼接路径完整保留，可从“处理路径”切换；文本锚点出现告警时，结果页会说明“部分内容可能缺失”，并提供用拼接路径重新处理的入口。
- 无法判断发言人的气泡会跳过并明确告警，不会静默猜成任意一侧。
- 群聊里可靠识别出的独立昵称行会作为发言人字段输出为 `[昵称] 正文`；在发言人已判定的气泡内，昵称几何条件不满足时保留原来的粘连文本，不删除昵称。

## 真机实测

同一台 OPPO、同一 ML Kit 引擎、同一微信真值：

- 文本锚点：6,359 ms，字符级 91.4%，发言人 39/41（39 条可识别消息全对），自检 21/21。
- 拼接基线：161,600 ms，字符级 90.6%，发言人同为满分。
- 小红书：13,945 ms，自检 42/42，累计位移 10,415 px（Mac Vision 基准 10,414 px）。

## Known limitations

- 深色模式尚未在真机验证。本版不调整颜色阈值；如果气泡颜色无法判断，会跳过该气泡、显示告警，并建议改用拼接路径重试。
- 正式发版验收集仍是约 27 秒的微信单聊与约 32 秒的小红书录屏。另有一段 44.2 秒微信群聊临时实测（较早普通运行人工核对为内容召回 59/60、自检 35/35）；随后导出的同素材诊断 bundle 离线得到 65 个独立昵称字段且未改变该 bundle 已有的 OCR 字符，但没有重新做消息级真值评分，也没有字符级真值、第二台设备或其他分辨率证据。其他 app 尚未验证。
- Android 仅验收竖屏；iOS 不在本次发布范围内。
