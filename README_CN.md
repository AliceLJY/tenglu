# 誊录

**把一段滚动录屏，变成一份干净的 Markdown 记录。全程在手机本地完成。**

对着微信聊天记录或小红书评论区录一段滑动的屏，誊录把帧拼成一张长图、做 OCR，交给你一份忠实、有序、可复制的完整记录——拿去喂任何你选的 AI。

名字取自宋代科举的誊录制度：专人把考生原卷一字不改地抄一遍，让阅卷官认不出笔迹。这正是产品的全部承诺：**忠实还原，零解读。**

## 为什么做

各家 app 都在替你总结内容、留下原料。誊录反过来：把原料给你，自己退开。

- **只还原，不分析。** 输出是纯文本记录（发言人 + 内容 + 顺序）。用什么模型读，是你的自由。
- **数据不出手机。** 无服务器、无 API key、无账号。APK 显式禁用了 `INTERNET` 权限——用飞行模式跑通完整流水线验证过。
- **不做内容审查。** 你的屏幕，你的数据，你的记录。

## 实测准确率

对照从微信数据库导出的真实记录（44 条消息）逐条验收：

| 指标 | 安卓（ML Kit） | macOS（Vision） | iOS（Vision，独立实现） |
|---|---|---|---|
| 字符级准确率 | 90.6% | 93.7% | 99.5% |
| 发言人归属 | 95.1% | 95.1% | **100%** |
| 消息顺序 | 100% | 100% | 100% |

发言人判定采气泡底色（微信绿 vs 白），不靠位置猜——跨三个平台三个 OCR 引擎，一次都没掉过。

## 工作原理

```
视频 → 稀疏预扫 → 检测滚动区（滞后阈值，自适应）
    → 固定间隔取帧 → 逐帧位移（DS=4 粗搜）
    → 选关键帧（回弹帧真实排除）→ 拼接（两级 SAD 精搜 + 页面跳转防护）
    → 分段 OCR → 按位置去重 → Markdown
```

踩出来的设计原则（完整工程记录见 [PLAN.md](PLAN.md)）：

- **宁可多不可少。** 重复能去掉，丢失补不回来。位移估计取保守值，重叠交给输出层收拾。
- **不解析结构。** 早期版本用正则去判"回复谁""点赞数"，48 条评论错 4 条；改成纯位置排序的文本后零错。读记录的 AI 比任何正则更懂结构。
- **每个自检都至少撒过一次谎。** 唯一可靠的裁判是拿输出对照解密出的真实记录。没有能对照的现实，就不知道自己的准确率。

## 状态

- **M1（已完成）**：最小安卓 APK——选视频 → 出记录 → 复制到剪贴板，逐阶段耗时可见。微信模式 + 通用模式。
- **M2（进行中，第 4 级）**：第 3 级已通过真机验收，输出逐字节一致，总耗时从 247.0 秒降到 164.3 秒。第 4.1 级只给相邻帧粗搜使用 quality 0.4 JPEG，选出的关键帧仍以 quality 1 重新抽取并做全分辨率拼接；真机收益与输出一致性等待验证。纯 JS 证明到不了目标后才考虑原生。
- 仅支持竖屏手机；折叠机请合起来用。iOS 版在计划中（算法已在 iOS Vision 上验证）。

## 开发方式

通过 AI 协作完成：Claude 负责设计与验收，Codex 负责实现，另有一套 iOS 独立实现交叉互证。每个里程碑都以可复现基准（`verify/run-node.js`）和真实数据评分（`verify/score.py`）把关——私人测试数据从不进入仓库。
